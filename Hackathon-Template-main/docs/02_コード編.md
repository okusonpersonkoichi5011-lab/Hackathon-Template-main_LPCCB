## 6. スタイリング設計

### 6-1. CSS 変数（globals.css）
ブランドカラーや余白などはすべて CSS 変数で管理し、変数だけ差し替えればテーマが切り替わる構造です。

```css
:root {
  --color-background: #f8fafc;
  --color-surface:    #ffffff;
  --color-primary:    #ebc528;  /* ライトパスの基調色（黄色） */
  --color-primary-foreground: #0f172a;  /* 黄色の上の文字 */
  --color-muted:      #f1f5f9;
  --color-muted-foreground: #64748b;
  --color-border:     #e2e8f0;
  --color-accent:     #0f172a;
}
```

### 6-2. Tailwind 連携
`tailwind.config.ts` で上記 CSS 変数を Tailwind の色トークンに紐付け：

```ts
colors: {
  background: "var(--color-background)",
  primary: "var(--color-primary)",
  "primary-foreground": "var(--color-primary-foreground)",
  // …
}
```

→ クラス `bg-primary` / `text-primary-foreground` で常に変数経由の色が当たります。

### 6-3. カスタム CSS クラス（globals.css）
| クラス | 内容 |
| --- | --- |
| `lp-animate-fade-up` | 初期表示用のフェードアップ |
| `lp-animate-slide-in-right` | 右からスライドイン（1 秒、TOPコピー用） |
| `lp-delay-100/200/300/400/500` | アニメーション遅延 |
| `lp-hover-lift` | ホバーで 3px 持ち上がる |
| `lp-card-hover-zoom` | ホバーで `scale(1.04)` |
| `lp-marquee` | 右→左の無限スクロール |
| `reveal-init` / `reveal-in` / `reveal-in-fade` / `reveal-in-scale` / `reveal-in-strong` / `reveal-in-slide-right` / `reveal-in-slide-left` | Reveal の各バリアント |
| `@media (prefers-reduced-motion: reduce)` | 上記アニメーション全てを無効化 |

## 7. フォーム設計

両フォーム（ContactForm / RecruitForm）の共通仕組み。

### 7-1. 3段階フロー
```tsx
const [step, setStep] = useState<"input" | "confirm" | "done">("input");

// 入力時：handleInputSubmit で validate → 通れば confirm 画面へ
// 確認時：handleSendSubmit で（本来 API 送信）→ done へ
// 修正：backToEdit で input へ戻る（state は保持）
```

### 7-2. バリデーション
- HTML 標準ポップアップを抑止するため `<form noValidate>`
- 自前 `validate(data)` がエラーオブジェクトを返す
- エラーがある項目だけ赤枠＋赤字エラーを表示
- 入力修正で `setErrors` が自動的にそのキーのエラーを削除

### 7-3. スクロール基準
- フォーム全体を `containerRef`（unmount しないラッパー）でつかみ、`scrollIntoView({ block: "start" })` でフォーム上端にスムーズスクロール
- `scroll-mt-24` で sticky ヘッダー分の余白を確保

### 7-4. 郵便番号 → 住所自動入力
```ts
// form-utils.tsx
export async function fetchAddressFromPostalCode(postalCode: string) {
  const digits = postalCode.replace(/[^0-9]/g, "");
  if (digits.length !== 7) return null;
  const res = await fetch(`https://zipcloud.ibsnet.co.jp/api/search?zipcode=${digits}`);
  // ...
}
```
- 公開無料 API（CORS 対応・API キー不要）
- ヒットなし／通信エラー時は `null` 返却 → ユーザーが手入力できる状態を維持

### 7-5. PDFファイル検証（採用フォーム）
**3段階の防御** を採用：

| 段階 | 場所 | 確認内容 |
| --- | --- | --- |
| 1 | クライアント | 拡張子 `.pdf` |
| 2 | クライアント | MIME `application/pdf`（空文字は他で代替） |
| 3 | クライアント | 先頭5バイト `%PDF-`（0x25 0x50 0x44 0x46 0x2D） |
| 1' 2' 3' | **サーバ `/api/upload-resume`** | 同じ3点を **再** 検証（クライアントを通り抜けた偽装にも対応） |

サーバ違反時は **400 Bad Request** ＋ JSON `{ "ok": false, "error": "..." }`。

```ts
// app/api/upload-resume/route.ts（抜粋）
export async function POST(request: Request) {
  const formData = await request.formData();
  const file = formData.get("file");
  if (!(file instanceof File)) return bad("ファイルが添付されていません。");

  if (file.size === 0) return bad("空のファイルはアップロードできません。");
  if (file.size > MAX_FILE_SIZE) return bad("ファイルサイズが上限を超えています。");

  if (!file.name.toLowerCase().endsWith(".pdf")) return bad("拡張子 .pdf のみ可能です。");
  if (file.type && file.type !== "application/pdf") return bad("MIME 不一致");

  const bytes = new Uint8Array((await file.arrayBuffer()).slice(0, 5));
  const isPDF = bytes[0]===0x25 && bytes[1]===0x50 && bytes[2]===0x44 && bytes[3]===0x46 && bytes[4]===0x2D;
  if (!isPDF) return bad("中身が PDF ではありません。");

  return NextResponse.json({ ok: true, name: file.name, size: file.size });
}
```

### 7-6. 雇用形態の条件分岐（採用フォーム）
- `EmploymentType = "fulltime-newgrad" | "fulltime-career" | "parttime"`
- `履歴書` は **全雇用形態で必須**
- `職務経歴` は **新卒採用では非表示**、それ以外は表示
- 職務経歴は **「テキスト入力」 ⇔ 「PDFアップロード」** をラジオで切替

## 8. アニメーション基盤

### 8-1. Reveal コンポーネント（IntersectionObserver）
```tsx
<Reveal variant="slide-right" delay={100}>
  <SomeContent />
</Reveal>
```
- マウント後に IntersectionObserver で監視
- viewport に入った瞬間 `reveal-init`（初期非表示）→ `reveal-in-*`（アニメ in）へクラス切替
- variant ごとに使う CSS クラスを切り替え
- `delay` を 100/200/300/400/500 から指定して順番に登場させる「スタッガー」も可能

### 8-2. キーフレーム（globals.css）
- `lp-fade-up` / `lp-fade-in` / `lp-scale-in` / `lp-fade-up-strong`
- `lp-slide-in-right` / `lp-slide-in-left`
- `lp-marquee`

### 8-3. アクセシビリティ
```css
@media (prefers-reduced-motion: reduce) {
  .reveal-in, .lp-animate-fade-up, .lp-marquee, ... {
    animation: none !important;
    opacity: 1 !important;
    transform: none !important;
  }
}
```

## 9. セキュリティ対策

### 9-1. レスポンスヘッダ（`next.config.ts`）
| ヘッダ | 値 | 目的 |
| --- | --- | --- |
| `X-Frame-Options` | `DENY` | クリックジャッキング対策 |
| `X-Content-Type-Options` | `nosniff` | MIME 推測拒否 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | リファラ最小化 |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), interest-cohort=()` | ブラウザ機能無効化 |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` | HTTPS 強制 |
| `X-XSS-Protection` | `0` | 旧フィルタ無効化（推奨） |

### 9-2. バージョン情報の非表示
- `poweredByHeader: false` で `X-Powered-By: Next.js` を削除
- `productionBrowserSourceMaps: false` でソースマップ非公開
- `compiler.removeConsole` で本番ビルドの `console.*` を削除（`error` は監視用に残す）

### 9-3. パストラバーサル防御（`middleware.ts`）
- `..` / `%2e` / `%2f` / `%5c` / `%00` / `\` を含むリクエストを **400 で拒否**
- 生 URL とデコード後パスの両方を確認
- 多重エンコードや混在ケースの保険も入っている

### 9-4. フォーム入力の防御的バリデーション
- 全入力に `maxLength` を設定（DoS 的入力抑制）
- メール／電話／郵便番号／ふりがな の形式検証
- ファイルは **PDF 限定の3段階防御**（拡張子＋MIME＋マジックナンバー＋サーバ側 400）

### 9-5. 外部リンク
- すべての `target="_blank"` に `rel="noopener noreferrer"` を付与

## 10. SEO・OGP・構造化データ

### 10-1. メタデータ（`app/layout.tsx`）
- 全ページ共通の `metadataBase` / `title.template` / `description` / `keywords` / `authors`

### 10-4. ファビコン
- `app/icon.png` を置くだけで Next.js が `<link rel="icon">` を自動生成
